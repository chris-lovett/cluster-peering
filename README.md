# Consul Cluster Peering on OpenShift

Cluster peering connects independent Consul clusters so services in different datacenters or cloud environments can communicate securely — without sharing a root CA or merging administrative control.

**Environment:** Consul Enterprise 2.0.1-ent · OpenShift · Kubernetes CRD-based peering

## Architecture

```
  cluster-01  (DIALER)                    cluster-02  (ACCEPTOR)
  ┌──────────────────────────┐               ┌──────────────────────────────┐
  │  PeeringDialer           │               │  PeeringAcceptor              │
  │  name: cluster-01        │               │  name: cluster-02             │
  │                          │               │  → generates peering-token    │
  │  ┌────────────────────┐  │   mTLS/443    │  ┌─────────────────────────┐ │
  │  │  mesh-gateway      │◄─┼───────────────┼──│  mesh-gateway           │ │
  │  └────────────────────┘  │               │  └─────────────────────────┘ │
  │  frontend                │               │  backend (exported)           │
  └──────────────────────────┘               └──────────────────────────────┘
```

**Key concepts:**

- **Peering token** — Single-use secret generated by the acceptor cluster. Regenerating it invalidates all prior tokens.
- **Mesh gateway** — Handles all cross-cluster mTLS traffic. Must have a public LoadBalancer address (`wanAddress.source: "Service"`).
- **Exported services** — Services are invisible across a peering by default. `ExportedServices` makes them discoverable.
- **Service intentions** — Consul enforces default-deny. Intentions must explicitly allow cross-cluster traffic.
- **Namespace** — All peering CRDs must be in the `consul` namespace. Applying them to `default` silently prevents reconciliation.

## How Peering Differs from WAN Federation

| Aspect | Cluster Peering | WAN Federation |
|---|---|---|
| Root CA | Independent per cluster | Shared |
| Admin control | Per-cluster independence | Centralized |
| Service visibility | Opt-in via `ExportedServices` | All services visible |
| Traffic routing | Via mesh gateways | Direct or via gateways |
