## Overview

### Key benefits

- Multi-cloud architectures
- Cross-team service sharing
- Disaster recovery and failover
- Administrative independence per cluster

## What is cluster peering?

Cluster peering connects independent Consul clusters for secure cross-environment communication.

### How it differs from WAN federation

- Clusters do not share a root Certificate Authority
- Each cluster maintains full administrative independence
- Communication requires explicit trust and policy

## Core components

### Peering token

- Single-use secret generated by the accepting cluster
- Establishes trust between clusters
- Regenerating the token invalidates previous tokens

### Mesh gateway

- Handles all cross-cluster traffic
- Encrypts and decrypts traffic via mTLS
- Routes traffic to healthy services
- Requires proper WAN address configuration

### Exported services

- Services are not shared by default
- Must be explicitly exported via `ExportedServices`
- Controls service visibility across clusters

### Service intentions

- Identity-based access control
- Enforced through mutual TLS
- Default behavior is deny

## Implementation workflow

Complete these steps in order:

1. Install Consul on both clusters
2. Configure mesh and proxy defaults
3. Generate and exchange the peering token
4. Establish the peering connection
5. Export services
6. Create service intentions
